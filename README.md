# ملاحظاتي

موقع ملاحظات عربي احترافي بواجهة RTL كاملة، يعمل كموقع ثابت (HTML/CSS/JS) ويتكامل مع **Supabase** للمصادقة وقاعدة البيانات. يمكن لكل مستخدم إنشاء حساب وتسجيل الدخول من أي جهاز، وتُحفظ ملاحظاته في مساحة خاصة لا يستطيع غيره الوصول إليها.

## المزايا

- **حسابات حقيقية:** تسجيل وإنشاء حساب بالبريد الإلكتروني وكلمة المرور عبر Supabase Auth.
- **مزامنة سحابية:** الملاحظات محفوظة في PostgreSQL وتظهر على مختلف الأجهزة بعد تسجيل الدخول.
- **عزل كامل بين المستخدمين:** سياسات RLS على جدولي `profiles` و`notes` تمنع أي وصول عابر للحسابات.
- **إدارة الملاحظات:** إضافة، تعديل، حذف، تثبيت، ألوان، وسوم، بحث فوري، وترتيب.
- **إعدادات الحساب:** تعديل الاسم، تغيير كلمة المرور، تصدير JSON، وحذف جميع الملاحظات.
- **تصميم متجاوب:** وضع فاتح وداكن، قائمة جانبية للجوال، واختصارات لوحة المفاتيح.
- **حماية إضافية:** منح صلاحيات محددة على مستوى الأعمدة، وليس مجرد الاعتماد على RLS فقط.

## التشغيل محليًا

الموقع ثابت ولا يحتاج إلى أدوات بناء أو `npm`.

```bash
# من داخل مجلد المشروع
python -m http.server 8080
```

ثم افتح `http://localhost:8080`.

> لا تفتح الموقع عبر `file://` إن أمكن؛ Supabase Auth يعمل بشكل أفضل عبر `http://localhost` أو HTTPS.

## إعداد Supabase

### 1) إنشاء المشروع

أنشئ مشروعًا جديدًا من [supabase.com](https://supabase.com)، ثم انتقل إلى **SQL Editor**.

### 2) تنفيذ مخطط قاعدة البيانات

انسخ محتوى الملف:

```text
supabase/schema.sql
```

وألصقه في SQL Editor ثم اضغط **Run**. ينشئ هذا الملف:

- جدول `public.profiles`
- جدول `public.notes`
- الفهارس و Triggers تحديث `updated_at`
- Trigger إنشاء الملف الشخصي تلقائيًا عند التسجيل
- سياسات RLS الكاملة
- صلاحيات الأعمدة الدنيا للمستخدمين المصادق عليهم

### 3) إعدادات المصادقة

من **Authentication → Providers → Email**:

- فعّل **Email**.
- أثناء التطوير يمكنك تعطيل **Confirm email** لتسجيل الدخول مباشرة بعد إنشاء الحساب.
- في الإنتاج، يُفضّل تفعيل تأكيد البريد.

من **Authentication → URL Configuration** أضف:

```text
Site URL:
https://<username>.github.io/<repo>/

Redirect URLs:
https://<username>.github.io/<repo>/
http://localhost:8080/
```

### 4) إضافة مفاتيح المشروع

افتح:

```text
assets/js/config.js
```

وضع القيم:

```js
window.MLZ_CONFIG = {
  SUPABASE_URL: 'https://YOUR-PROJECT.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR_ANON_OR_PUBLISHABLE_KEY'
};
```

يمكنك نسخهما من **Project Settings → API**.

> **مهم جدًا:** استخدم `anon` أو `publishable` key فقط. لا تضع `service_role` key في `config.js` أو أي ملف يُرفع إلى GitHub أو GitHub Pages. مفتاح `service_role` يتجاوز RLS ويجب أن يبقى على الخادم فقط.

### 5) تشغيل الموقع

شغّل خادمًا محليًا كما في الأعلى، ثم جرّب إنشاء حساب. إن كان تأكيد البريد مفعّلًا، افتح رسالة التأكيد أولًا ثم سجّل الدخول.

## البنية

```text
index.html
assets/
  css/styles.css
  js/config.js    # إعدادات Supabase العامة (URL + anon key)
  js/store.js     # المصادقة و CRUD الملاحظات عبر Supabase
  js/app.js       # منطق الواجهة
supabase/
  schema.sql      # الجداول + RLS + Triggers + الصلاحيات
```

## نموذج البيانات

### `public.profiles`

| العمود | النوع | الوصف |
|---|---|---|
| `id` | `uuid` | مفتاح أساسي مرتبط بـ `auth.users.id` |
| `email` | `text` | بريد المستخدم |
| `display_name` | `text` | الاسم المعروض |
| `created_at` | `timestamptz` | تاريخ الإنشاء |
| `updated_at` | `timestamptz` | آخر تحديث |

### `public.notes`

| العمود | النوع | الوصف |
|---|---|---|
| `id` | `uuid` | معرف الملاحظة |
| `user_id` | `uuid` | صاحب الملاحظة (افتراضيًا `auth.uid()`) |
| `title` | `text` | العنوان (حتى 120 حرفًا) |
| `body` | `text` | المحتوى (حتى 20,000 حرف) |
| `tags` | `text[]` | حتى 6 وسوم |
| `color` | `text` | لون البطاقة |
| `pinned` | `boolean` | مثبتة أم لا |
| `created_at` | `timestamptz` | تاريخ الإنشاء |
| `updated_at` | `timestamptz` | آخر تحديث |

## ملاحظات أمنية

- **RLS إلزامية:** كل عمليات `select/insert/update/delete` مقيّدة بـ `auth.uid() = user_id`.
- **صلاحيات الأعمدة:** لا يستطيع العميل تغيير `user_id` أو `created_at` أو `id` عند التحديث.
- **بدون أسرار في الواجهة:** `anon` key عام بطبيعته، والأمان الحقيقي من RLS. `service_role` ممنوع في المتصفح.
- **اتصال مشفّر:** Supabase يستخدم HTTPS/TLS، مع تشفير التخزين على مستوى الخادم.
- **لا يوجد تشفير طرفي (E2E) في هذه النسخة:** الاعتماد على Supabase Auth + RLS + TLS. هذا يسمح باستعادة كلمة المرور وإدارة الحساب من لوحة Supabase، لكنه يعني أن بيانات الملاحظات قابلة للقراءة من جهة الخادم/المشرف.
- **التصدير غير مشفّر:** ملف JSON يحتوي ملاحظاتك كنص واضح؛ احتفظ به في مكان آمن.
- **حذف الحساب:** الواجهة تتيح حذف جميع الملاحظات. لحذف الحساب نفسه نهائيًا، احذفه من **Authentication → Users** في Supabase؛ سيؤدي ذلك إلى حذف الملف الشخصي والملاحظات تلقائيًا بفضل `on delete cascade`.

## الانتقال من النسخة المحلية القديمة

النسخة السابقة كانت تخزّن الحسابات والملاحظات في `localStorage` وتشفّرها بمفتاح مشتق من الرقم السري. لا يمكن ترحيلها تلقائيًا إلى Supabase لأن مفتاح فك التشفير كان محليًا. إن كانت لديك ملاحظات قديمة مهمة:

1. افتح النسخة القديمة في المتصفح نفسه.
2. سجّل الدخول بالرقم السري القديم.
3. صدّر الملاحظات إلى JSON.
4. أنشئ الحساب الجديد في Supabase، ثم أعد إنشاء الملاحظات أو استوردها يدويًا.

## النشر على GitHub Pages

1. ارفع محتويات المشروع إلى مستودع GitHub (الفرع `main`).
2. من **Settings → Pages** اختر **Deploy from a branch** ثم `main` و`/ (root)`.
3. أضف رابط الموقع في **Supabase → Authentication → URL Configuration**.
4. تأكد من وجود `.nojekyll` في جذر المستودع.
